# Module 2 – Technical validation checklist

This document maps every Unity concept required for the evaluation to its implementation in
the VR Science Lab, the GameObject that carries it, the script or component responsible, and
the exact steps to demonstrate it. It also explains how to open, run, bake and test the scene.

Scene: `Assets/Module2_Equipment/Scenes/Module2_Lab.unity`
(generated by **VR Science Lab > Module 2 > Build Lab Scene**).

## 2. How to open and run the scene

1. Install **Unity 6000.3 LTS** (project version 6000.3.16f1) with Unity Hub and open the
   `VRScienceLab` folder. Packages are downloaded on first open.
2. If Unity asks to enable the **new Input System backends**, answer **Yes** (the editor restarts).
3. Menu **VR Science Lab > Module 2 > Set Up Project** – imports the TextMeshPro essential
   resources and the XR Interaction Toolkit samples (Starter Assets, simulators). Run it once.
4. Menu **VR Science Lab > Module 2 > Build Lab Scene** – generates materials, meshes,
   textures, prefabs, the NavMesh and the scene, then opens it.
5. Press **Play**.

## 3. How to bake the NavMesh

The builder bakes it automatically. To bake again after moving furniture:

* Menu **VR Science Lab > Module 2 > Bake NavMesh**, then save the scene; or
* select `Environment` in the Hierarchy and click **Bake** on its *NavMesh Surface* component.

Settings: *Collect Objects = Current Object Hierarchy*, *Use Geometry = Physics Colliders*,
agent type *Humanoid* (radius 0.5 m, which leaves a safe margin around furniture for the
0.3 m robot), voxel size 0.05. Show the result with the *AI Navigation* overlay in the Scene view
(*Show NavMesh*). Movable obstacles (cart, user, screen stands) are not baked: they carve the
NavMesh at runtime with `NavMeshObstacle`.

## 4. Testing without a headset (XR simulator)

`Lab Systems/XR Simulator Loader` instantiates the XR Interaction Toolkit simulator
automatically when no headset is active. In the Game view: mouse looks around, **WASD**
moves, the on-screen simulator panel lists the keys that switch between head, left and
right controller, **Grip** (G) and **Trigger** (T). A left click is sent as Trigger over a
screen and as Grip elsewhere (XR Interaction Simulator 3.5 and newer). The simulator also uses
the keys W A S D Q E, the arrows, Tab, H, M, R, 1, 2, I J K L, [ ], Space and backtick: the
sample shortcuts M, K, L, I and the brackets act on both. Change a shortcut on
`Lab Systems/Lab Keyboard Shortcuts` in the Inspector if that gets in the way.

## 5. Testing in VR

Edit > Project Settings > XR Plug-in Management: enable **OpenXR**, add your controller
interaction profile, run **Project Validation > Fix All**, connect the headset (Quest Link /
SteamVR) and press Play. The simulator is skipped automatically. Left stick moves, right
stick turns / teleports (Starter Assets defaults).

## 6. Automated tests

Window > General > **Test Runner** > PlayMode > Run All.

* `Module2InstrumentTests` – the four instruments (state machines, measurements).
* `Module2LabSystemsTests` – instantiate / destroy, scaling and moving, rotation, GameObject
  search, gravity + collision + trigger weighing, NavMesh navigation with stop / resume,
  measurement log and reset, and three end-to-end tests that load the generated lab scene.
* `Module2StationCabinetRobotTests` – combined heating station (independent heater and timer,
  heating of a container), cabinet doors and stored-object count, robot control panel (every
  command, stop, return, missing NavMesh, occupied stop point), and four end-to-end tests on the
  generated scene: station buttons, raycasters on every screen, every robot screen button
  clicked through the EventSystem with the robot driving to each station, and the cabinet
  (objects resting on their shelves, doors, a beaker taken to the scale, thermometer and heating
  surface and put back).

## 7. Suggested demonstration order (about 6 minutes)

1. **Enter the lab** – welcome screen, look around the room (benches, storage, fume hood,
   windows, diagrams, clock and fan moving). *BEGIN SESSION*.
2. **Instruments** – scale: POWER, place a weight, TARE. Heating station: ON, watch the element
   glow, OFF; START, PAUSE, rotate the timer head. Thermometer: MEASURE.
   **Cabinet** – open a door (Grip on the handle), take a beaker with water to the scale, to the
   thermometer, then onto the heating surface (it warms up); put a test tube back in the rack.
3. **Samples** – create a beaker and a flask, select, send to the scale pan (trigger ring +
   mass), enlarge it (mass rises), send to the thermometer dock (temperature), remove one.
4. **Physics and collisions** – drop the ball and a weight; show the collision line.
5. **Search** – *FIND* buttons: beacon and report; *HEAVIEST*.
6. **Robot** – GO TO DIGITAL SCALE, STOP ROBOT, RESUME, GO TO STORAGE CABINET while it moves,
   RETURN TO STARTING POSITION; push the cart into its way; start the tour.
7. **Summary and reset** – RECORD two measurements, show the table and statistics,
   *RESET LABORATORY*.
8. **Avatar** – look down at the coat and gloved hands; F12 for the outside view.

                           ProceduralMeshFactory, ProceduralTextureFactory, ProjectBootstrap

The four instruments do not reference each other or any of the new systems. The new
components read them through their public properties and events only, so the module can be
merged into the group project as one folder.
